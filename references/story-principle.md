- 按顺序完成如下三个步骤。

  ## ① 用户意图对齐

  > 如果 Step2 需求对齐已完成，以下问题优先采用对齐结果，不重复向用户提问。

  在构建 `STORY.md` 时，必须先用一段话回答清楚以下 5 个问题：

  - **目标受众**：这份 PPT 在什么场合给谁看？汇报 / 路演 / 教学 / 评审 / 发布 / 内训？
  - **受众导向（强制）**：受众决定内容的详略与取舍——给**决策者**（老板/投资人/评委）讲结论和决策点，重「所以呢」，不铺过程；给**执行者**（同事/下属）讲过程和方法，重「怎么做」；给**同行**（专家/评审）讲深度和对比，重「凭什么」。受众不明确时，必须向用户澄清，禁止按「万能受众」写一套给谁都一样的内容。
  - **核心目标**：讲完后希望观众相信什么、记住什么、做什么？
  - **PPT 长度**：总页数预估（决定 Hero 页配额：10 页中 2-3 页、15 页中 3-4 页）。
  - **视觉调性**：用 3-5 个词锁定（如"禅意克制 / 学术严谨 / 发布会式 / 政务红色 / 儿童卡通"）。
  - **内容边界**：哪些必讲？哪些不讲？哪些禁碰？

  意图块未完成 → 禁止进入第②步。

  ### 数据真实性门禁（强制，所有数据类内容）

  凡 PPT 涉及数字、百分比、金额、排名、年份、市场规模、增长率、行业数据等任何具体数据：

  1. **来源三选一**：每个数字必须有来源——来自联网搜索查到的真实数据（无联网能力时一律占位） / 来自用户上传的材料 / 明确标注「待核实」占位。**禁止凭模型记忆编造任何具体数字**。
  2. **查不到就占位**：搜不到确定数据时，该处写「XX（请核实）」占位，并在澄清环节提醒用户补充，而不是瞎填一个数。
  3. **材料优先**：用户提供了材料/附件时，数据以材料为准，联网搜索只用于补充材料缺失的行业背景。
  4. 拿不准的数字，宁可不写或标「待核实」，也不能编。编造数字是 PPT 的最高级别错误。

  ### 叙事钩子（封面强制）

  封面页不能只是「标题 + 副标题」，必须有一个**钩子**——制造认知缺口，让观众第一眼就想听下去。钩子四选一：

  - **反直觉的事实**（与常识相悖的真相）
  - **尖锐的问题**（直指观众痛点的提问）
  - **惊人的数字**（冲击力的真实数据）
  - **强烈的对比**（前后/大小/新旧的反差）

  钩子必须真实（同样受数据真实性门禁约束），并写进封面页的 description。

  ### 页数边界

  若用户明确要求页数，或上传材料/文档内容量明显超出单次 PPT 合理承载（一般 8~20 页），必须先向用户提示「内容量较大，建议拆分或精简」并给出建议页数，让用户确认后再生成；禁止不提示就闷头塞成一个超长 PPT，或擅自砍掉用户材料中的内容。

  ## ①.5 全篇叙事骨架（SCQA + 金字塔原理 + Action Title）

  > 本步决定「全篇怎么铺陈」，与 content-playbook 的「按类型必讲骨架」（决定每页讲什么）互补。写完意图块后、进第②步前，先确定全篇叙事骨架。

  ### 金字塔原理（结论先行，强制）

  全篇结构必须「结论先行、自上而下」：

  - **一句话核心结论**：全篇第一页（或执行摘要页）先给出整份 PPT 的**唯一 takeaway**——观众听完只能记住一句，是什么？
  - **章节 = 子结论**：每个章节的第一页是「子结论」，支持核心结论；章节内的页是「证据/数据/案例」支撑子结论。
  - **每页标题 = 观点句**（见下方 Action Title），不是名词短语。
  - 反例：目录标题写成「市场分析」「竞品情况」这种名词；正例：写成「市场仍在增长，但窗口正在收窄」这种观点句。

  ### Action Title（每页标题是完整结论句，强制）

  每页标题必须是一句**完整观点**（主题 + 结论），禁止名词短语、禁止「目录味」标题：

  - ❌ 「市场分析」「项目背景」「竞品情况」
  - ✅ 「当前最大问题不是流量，而是转化率没闭环」
  - ✅ 「行业趋势：变革加速，不进则退」

  ### SCQA 叙事骨架（按 PPT 类型选，全篇 storyline）

  全篇按「类型 → 叙事骨架」选择铺陈节奏（借鉴麦肯锡 SCQA / 金字塔）。选定后，各章节按骨架顺序排列，不是随意堆砌：

  | PPT 类型 | 叙事骨架 | 章节流 |
  |---|---|---|
  | 汇报 / 总结 | 结论先行（Classic） | 结果 → 证据 → 细节 → 下一步 |
  | 产品 / 销售 | 问题-方案（Problem-Solution） | 痛点 → 方案 → 价值 → 证明 → CTA |
  | 培训 / 教学 | 渐进（Shallow→Deep） | 基础 → 核心 → 进阶 → 练习 |
  | 路演 / 融资 | SCQA（Situation→Complication→Question→Answer） | 现状 → 冲突 → 问题 → 答案 |
  | 活动 / 推广 | 情绪（Emotional） | 钩子 → 共鸣 → 高潮 → 行动 |

  **SCQA 四步说明**（路演/融资类必用）：
  - **Situation（现状）**：先讲一个共识性的背景，让观众点头；
  - **Complication（冲突）**：抛出打破平衡的变局/痛点，制造张力；
  - **Question（问题）**：由此引出「那怎么办」的核心问题；
  - **Answer（答案）**：给出方案/建议，这是全篇的高潮与落点。

  > 若不确定类型，默认用「结论先行」；叙事骨架写进 STORY.md 意图块或布局骨架，作为章节排列的依据。

  ## ② 构建页面布局骨架

  使用一段话回答清楚以下几个问题：

  - **页面总数与分章**：列出每个章节包含哪几页。
  - **目录↔章节扉页契约（强制）**：目录（catalog）里声明了 N 个章节，全篇就**必须有且仅有 N 个 `type: section` 章节扉页**，一一对应，不允许合并、跳过或缺失。每个扉页的**编号（01..N 连续）、标题文字、页码区间**都必须与目录对应条目**逐字一致**。骨架里要显式把"目录第 k 章 → 第几页是它的 section 扉页"标注出来，确认 N 个扉页齐全且编号连续后，才算骨架成立。
  - **Hero 页定位**：在骨架上**先标出**哪几页是 Hero 页（封面、结束页默认 Hero；中段按内容高潮选 1-2 页）；确认 Hero 占比落在 20–30%、且任意两个 Hero 页之间至少间隔 1 个 Supporting 页。
  - **rhythm 曲线**：给每页标 peak / valley / transition；连续 ≥ 3 页 valley 必须插入 peak 或 transition 打破沉闷；章节切换处用 transition。
  - **非对称版式预算**：从 §版式速查"非对称版式"表中**先挑出 ≥ 40% 的页面**用非对称；剩余页才允许用对称版式。
  - **对称版式预算**：全篇最多 2 页可用此版式；先决定用在哪两页，其他页一律换非对称版式。

  骨架未确认 → 禁止进入第③步。

  ## ③ 构建页面大纲

  页面大纲按照如下字段展开：

  | 字段           | 说明                                                         | 示例                                       |
  | -------------- | ------------------------------------------------------------ | ------------------------------------------ |
  | `title`        | 页面标题                                                     | 市场规模与增长                             |
  | `type`         | 页面类型：cover / catalog / section / content / ending       | content                                    |
  | `role`         | **页面角色**：hero（视觉高潮）/ supporting（信息承载）/ transition（章节过渡） | hero                                       |
  | `rhythm`       | **叙事节奏**：peak（高潮）/ valley（蓄力）/ transition（转场） | peak                                       |
  | `layout`       | 版式—— 见下方版式速查                                        | 巨型数字+洞察                              |
  | `visual`       | 视觉元素—— 标注该页核心视觉载体（必含 L1 主视觉文件名占位）  | L1: market_growth.png（占右60%）           |
  | `visual_role`  | **视觉叙事角色**：anchor（视觉锚点，这页的图是主角）/ atmosphere（氛围营造，图做背景）/ evidence（论据支撑，图证观点） | anchor                                     |
  | `density`      | 信息密度估算—— `字数约XXX / 图片 N 张 / 留白约XX%` 三段式    | 字数约220 / 图片 1 张 / 留白约20%          |
  | `anti_pattern` | **明确禁止的版式/模式**—— 列出这页不能用的布局方式           | 禁止等宽卡片横排                           |
  | `image_requirements` | **图片需求**（可选，无图页省略）：`视觉类型 / 描述 / 风格` 三段式。有图页才写；无图页不写（逐页生成时删掉 Image） | `数据图 / 市场规模增长曲线（2022-2026），蓝紫色渐变商务风 / 与 DESIGN 配色一致` |
  | `description`  | 1-2句话描述本页内容；**含关键数据的页必须写成"数据+判断"两段式**（见下方 §数据必须落点） | 增长16.3%——行业仍在增长，但高基数后增速转入温和阶段 |

  ------

  ### image_requirements 判定规则（何时有图）

  `image_requirements` 只在「该页确实需要图」时写，**默认无图**：

  1. **默认不用图**：能用文字+版式+结构图表达清楚的页，不写 image_requirements（逐页生成时删掉 Image）；
  2. **有图页 ≤40%**：整个 PPT 有图页数 ≤ 总页数 40%（10 页最多 4 页有图）。超过就砍掉次要页的图；
  3. **必须用图的场景**：人物/产品介绍、视觉特效演示、数据可视化（曲线/柱状/饼图）、真实场景示意图、竞品对比图——这些才写；
  4. **写什么**：`视觉类型 / 描述 / 风格` 三段式——类型（数据图/流程图/对比图/示意图）、描述（具体内容与信息）、风格（与 DESIGN 配色一致，如蓝紫渐变商务风）；
  5. **与 visual 字段协同**：`visual` 字段仍写 L1/L2/L3 视觉载体；有 image_requirements 的页，visual 通常对应 L1 主视觉（图片占位）。

  ------

  ### 数据必须落点（"所以呢"）

  STORY 阶段做的是「观点组织」，不是「信息摘录」。关键数值 / 比例 / 排名 / 年份 / 实验结果后，必须补一句判断——三选一：

  - **含义解释**：这个数字说明技术/行业处于什么状态（`14nm → 沟道栅长被压缩到必须精确管理的尺度`）
  - **业务影响**：这个数字对业务/决策意味着什么（`增长16.3% → 行业仍在增长，但高基数后增速转温和`）
  - **管理启示**：据此该做什么判断（`不能只用总量增长判断机会，必须看细分结构和商业质量`）

  反例：只写 `2026年销量预计增长16.3%` 就收尾——这是信息板，不是汇报稿。此为 STORY 阶段职责，禁止推给 DESIGN。

  ------

  ### 版式速查（layout 字段可选值）

  > 版式分为"对称版式"和"非对称版式"两类。**非对称版式使用比例必须 ≥ 40%**。

  #### 对称版式

  | 版式                | 适用场景                                                  | 典型结构                        |
  | ------------------- | --------------------------------------------------------- | ------------------------------- |
  | `全屏视觉+大标题`   | 封面、章节过渡页                                          | 全屏底图 / 渐变 + 居中大标题    |
  | `N卡片横排`         | 功能对比、并列概念（2-4 卡片）**⚠️ 全篇最多2页使用此版式** | 等宽卡片横向排列                |
  | `图表+洞察`         | 数据分析页                                                | Chart / Table 主体 + 洞察标注框 |
  | `居中金句/巨型数字` | 核心观点、里程碑页                                        | 居中大字 + 装饰光晕             |
  | `上下分栏`          | 对比、before/after                                        | 上下两区并排                    |

  #### 非对称版式（优先使用）

  | 版式              | 适用场景               | 典型结构                                   |
  | ----------------- | ---------------------- | ------------------------------------------ |
  | `左大图+右侧文字` | 视觉叙事页、产品展示   | 左侧大图占 55-65% + 右侧文字卡片           |
  | `全幅图+骑线文字` | Hero页、封面、叙事高潮 | 全幅背景图 + 文字从一侧骑入，占图面 30-45% |
  | `非对称双栏`      | 对比论述、主次信息     | 宽窄比 60:40 或 65:35，宽侧放大图或主内容  |
  | `巨型数字+洞察`   | 数据冲击页             | ≥ 48px 锚点数字占视觉重心 + 小字洞察环绕   |
  | `上大图+下方卡片` | 产品/场景展示          | 上半部大图占 55-65% + 下半部卡片           |
  | `左标题+右内容`   | 数据密集型、列表型     | 左侧色块标题栏（窄，30-35%）+ 右侧内容区   |

  **版式选择约束**：

  - 相邻页面必须用不同版式（含非对称版式之间也不得相邻重复）
  - **连续 ≥ 2 页使用对称版式 → 第 2 页必须改为非对称版式**
  - `N卡片横排` 全篇最多 2 页使用
  - Hero 页**禁止**使用 `N卡片横排`
  - **非对称版式多样性**：全篇 `左大图+右侧文字` 与 `非对称双栏` 合计出现次数 ≤ 全篇页数的 40%。

  ------

  ### 视觉锚点配置

  逐页确定 `visual_role`，决定该页"图"的叙事身份：

  - **anchor**：图是这页的主角（必须对应 Hero 页或视觉冲击页，至少占 B 区 ≥ 40% 或配 ≥ 48px 锚点数字）。
  - **atmosphere**：图做背景烘托（适用于章节过渡、全幅图骑线文字页）。
  - **evidence**：图证观点（数据图、流程图、产品对比图，从属于文字论述）。

  `visual_role` 必须与 `role` 协同：Hero 页的 `visual_role` 默认是 `anchor`，否则该 Hero 不成立——回到 §Step 2.5 ③ "Hero 页升级"动作处理。

  ------

  ### 版式与内容必须匹配

  逐页选 `layout` 时，必须按"内容类型 → 最佳版式"匹配，如下表格是一些参考，请充分发挥你的创造力，禁止"想用某版式就硬凑内容"：

  | 内容类型            | 最佳版式                              | 必须避免（AI 味）               |
  | ------------------- | ------------------------------------- | ------------------------------- |
  | 核心数据 / KPI      | `巨型数字+洞察`                       | `N卡片横排`（数据装进等宽卡片） |
  | 产品 / 场景展示     | `左大图+右侧文字` / `上大图+下方卡片` | 50:50 等分双栏                  |
  | 观点 / 金句         | `居中金句/巨型数字`                   | 装进引言卡片                    |
  | 对比论述            | `非对称双栏`（60:40 / 65:35）         | `上下分栏`（等分）              |
  | 流程 / 步骤 / 架构  | `非对称版式`                          | `N卡片横排`                     |
  | 视觉叙事 / Hero     | `全幅图+骑线文字`                     | 标题 + 装饰小图（200×70）       |
  | 数据密集列表        | `左标题+右内容`                       | 等宽四卡                        |
  | 复杂架构 / 多维数据 | `非对称版式`                          | 单栏线性列表                    |
  | 趋势演进 / 概念对比 | `非对称双栏`                          | 左右等分双栏                    |

  同时核对版式约束：相邻页不重复版式 → 连续 ≥ 2 页对称必须打断 → Hero 禁用 `N卡片横排`。

  ------

  ### anti_pattern约束

  每页必须显式写出 `anti_pattern`——不是抽象的"避免 AI 味"，而是基于本页 `role / rhythm / layout` 写出**具体禁止项**。例如：

  - Hero 数据冲击页：`anti_pattern: 禁止等宽卡片横排；禁止把核心数字塞进图表卡角落；禁止 L3 角标顶替 L1`
  - 章节过渡页：`anti_pattern: 禁止四卡片预览；禁止铺满正文段落`
  - 产品展示页：`anti_pattern: 禁止 50:50 等分双栏；禁止把产品图缩小为 200×70`

  `anti_pattern` 字段写得空泛（如"避免单调"）= 不合格。

  ------

  ### 页面角色与叙事节奏规则

  **角色分配约束**：

  - Hero 页占整份 PPT 的 **20-30%**（10 页中 2-3 页，15 页中 3-4 页）
  - Hero 页不能相邻，两个 Hero 页之间至少间隔 1 个 Supporting 页
  - 封面和结束页默认为 hero

  **节奏约束**：

  - Peak（高潮）页：视觉爆发，允许更大留白，强调色占比可达 15-20%
  - Valley（蓄力）页：信息密度高，颜色更克制，为下一个高潮蓄势
  - Transition（转场）页：章节切换，极简大字 + 简单视觉
  - 连续 ≥ 3 页同为 valley → 需要插入一个 peak 或 transition 打破沉闷

  ------

  ### visual 字段标注规则

  每页 `visual` 必须给出 **L1（主视觉）/ L2（支撑图）/ L3（角标）** 中至少一项；纯结构页（目录、对照表）允许仅 L3。

  | 标注示例                                | 含义                                 |
  | --------------------------------------- | ------------------------------------ |
  | `L1: longchang_mist.png（占左 55%）`    | 主视觉，必须铺满某一栏或卡片整体     |
  | `L2: brush_paper.png（占右上 280×180）` | 支撑图，与正文段落并排               |
  | `L3: 朱砂方印（角标）`                  | 母版徽标，全篇位置一致               |
  | `Chart(柱状图)`                         | 数据图表，注明类型                   |
  | `Diagram(时间轴)`                       | 图示组件，注明类型                   |
  | `FAIcon列表`                            | 图标化要点卡片                       |
  | `大数字`                                | 关键数据极大化呈现——必须标注最小字号 |


  > **流程/阶段/架构类内容的 visual 强约束（防"卡片化"降级）**：当一页的核心信息是「流程推进 / 阶段任务分解 / 并行任务关系 / 层级架构」时，`visual` 字段**必须写具体的结构图类型**（流程图 / 时间轴 / 问题树 / 树状图 / 组织图 / 价值链 / 矩阵），层级必须是 **L1（主视觉）**，且 `visual_role` 必须是 **`anchor`（图是主角）**——**禁止**把这类页的 `visual` 降级写成 `阶段分区卡 + 编号块 + 交付物清单` 这种「卡片/清单式」表述，**禁止** 降级为 `L2`（支撑图），也**禁止** `visual_role` 标成 `evidence`（论据）或 `atmosphere`（氛围背景）。因为「卡片/清单 + L2 + evidence」是模型写阶段页最省力的退化写法，会把"EVT 四大并行任务"这种该画树状图的结构压平成"目标/输出/准出"三块并列列表——这正是 slides-engine 曾输给 tencent 的直接原因（tencent 把 EVT 定为 `L1: EVT流程图SVG` + `anchor`，我们退化成 `L2: 阶段分区卡` + `evidence`）。

  ### STORY.md 的Checklist

  - ❌ 全篇 Hero 页 < 2 个或 > 35%
  - ❌ 连续 ≥ 3 页同为 supporting + valley（无视觉起伏）
  - ❌ 全篇 `N卡片横排` 出现 ≥ 3 次
  - ❌ 非对称版式占比 < 40%
  - ❌ 任意相邻两页版式相同（含非对称版式之间）
  - ❌ `左大图+右侧文字` 与 `非对称双栏` 合计超过全篇 40%（版式单调）
  - ❌ 任意页缺少 `role` / `rhythm` / `visual_role` / `anti_pattern` 字段
  - ❌ 含关键数据的页只摆数字、不给判断（信息板而非汇报稿）
  - ❌ 数据页数字无来源、或疑似凭记忆编造（未联网核实、非材料来源、也未标「待核实」）
  - ❌ 封面页无钩子（只是标题+副标题，没有反直觉事实/尖锐问题/惊人数字/强烈对比）
  - ❌ 受众不明确却未澄清，直接按「万能受众」写内容
  - ❌ 全篇无「一句话核心结论」（没有结论先行，章节顺序无逻辑主线）
  - ❌ 每页标题是名词短语而非观点句（如「市场分析」「项目背景」，违反 Action Title）
  - ❌ `type: section` 章节扉页的数量 ≠ 目录声明的章节数（目录 N 章却缺扉页 / 多扉页）
  - ❌ 章节扉页编号不连续（非 01..N）或与目录对应条目的编号、标题、页码区间不一致
